# Beginner UI polish — approved scope

Product Owner approved approach A (incremental polish) on 2026-09-09 and delegated continuous execution. Baseline: 4f6b4db. Retain the existing shell, pages, task state machine, providers, file operations and credential transactions.

1. Shared controls: white background, one-pixel neutral border, 6–8 px corners, one downward chevron for selects, visible hover/focus/disabled states. Dark primary actions, outlined secondary actions. Preserve object names, keyboard operation and minimum click targets; never hide essential actions at 900×640.
2. Default template: show localized catalog names in a non-editable select; store IDs only on explicit selection. Empty ID means the existing first-template fallback. Unknown/deleted ID is visible as unavailable and blocks Save until resolved; opening the page must not rewrite configuration. Cancel retains the old value.
3. Template editing: translated field names and language names; readable date examples and separator labels. Technical values stay unchanged internally. Organization select must reflect the saved mode, including when switching between templates; display changes never modify draft data. Vocabulary source badges become 内置/自定义/AI 建议.
4. Watch form: visible 选择文件夹 buttons; content-sized card capped to available height with scrolling. Mode description follows the actual switch: off means review before disk changes, on means automatic rename/move with existing safety guards. Preserve recursive/default values and configuration workflow.
5. Batch empty state: common supported format examples plus 添加文件 → 查看建议 → 应用更改. Explain that generating/editing suggestions does not change originals. Retain real drop handling and file/folder buttons. No additional onboarding modal or permanent preview sidebar.

Validation: red/green tests for state/value mappings and interactions; Windows native screenshots at 1000×700 and 900×640, zh-CN/en-US where text length matters, zero runtime warnings, real navigation/click/scroll/keyboard; full pytest, acceptance, build, isolated executable smoke. Use only temporary synthetic files and fake credentials. No real network, push or release. Keep existing user templates, settings, shortcut and private research unchanged. Formal golden files are not silently updated: if approved visual changes differ, record exact affected cases and seek a controlled baseline decision rather than weaken comparisons.
