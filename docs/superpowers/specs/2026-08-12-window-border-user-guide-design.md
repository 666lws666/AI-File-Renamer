# 序匣窗口边界与离线用户说明书设计

日期：2026-08-12  
状态：Product Owner 已批准设计方向，等待书面规格复核

## 1. 目标

本次改动解决两个明确问题：

1. 序匣使用无边框 Windows 窗口，白色界面在浅色桌面或资源管理器背景上缺少可辨认的外轮廓。
2. 仓库现有 `USER_GUIDE.html` 已过时，包含开发阶段、安装 Python、双 Provider 路由、价格及“多模态未实现”等错误信息，不能作为当前 1.0.0 Windows 产品说明书。

最终交付必须同时包含清晰的窗口边界，以及完全离线、面向普通使用者、与当前真实功能一致的 HTML 用户说明书。

## 2. 非目标

- 不更改 AI Provider、文件扫描、重命名、Undo、Watch 或多模态业务逻辑。
- 不新增软件内完整帮助中心或内嵌浏览器。
- 不展示 API 价格、货币费用或金额预算。
- 不要求用户同时配置两个 Provider。
- 不访问真实 API、真实 API Key 或真实 Credential Manager。
- 不更新现有正式 Golden，除非 Product Owner 另行明确批准。
- 不 push 或公开发布。

## 3. 窗口边界设计

### 3.1 视觉

- 在应用最外层叠加 1px 内描边。
- 描边颜色固定为稍深的中性灰 `#94A3B8`。
- 描边不占用布局空间，不改变现有 1000×700 参考尺寸或 900×640 最小尺寸。
- 描边位于所有页面内容之上，但不接收鼠标事件，不影响标题栏拖动、窗口按钮、导航或页面操作。
- 普通窗口状态显示四边轮廓。
- 最大化和全屏时隐藏轮廓，避免屏幕边缘双线、裁切或与系统边缘冲突。
- 最小化状态无需单独渲染要求。

### 3.2 实现边界

- 在 QML `Shell` 或最外层窗口添加一个独立、命名清晰的边界组件；不在各页面重复绘制。
- 在 `DesignTokens.qml` 中集中定义边界颜色和宽度。
- 边界可观察状态必须依赖真实窗口 visibility，而不是测试专用布尔值。
- 边界组件必须设置 `enabled: false` 或等价的非交互行为，保证不吞鼠标事件。

### 3.3 验收

- 1000×700 普通窗口：四边 1px 轮廓连续、颜色正确。
- 900×640 普通窗口：四边轮廓连续，无内容裁切。
- 最大化：轮廓不可见。
- 恢复普通窗口：轮廓重新出现。
- 标题栏拖动、最小化、最大化、关闭和导航点击不受影响。
- 原生 Windows 截图在浅色背景上可以明确判断窗口边界。
- QML runtime warnings 为 0。

## 4. HTML 用户说明书设计

### 4.1 交付形式

- 面向用户的入口文件：仓库根目录 `序匣用户手册.html`。
- 英文安全文件名镜像不作为第二份内容源；只保留一份权威 HTML，避免内容分叉。
- 静态图片和局部资源位于根目录 `user-guide-assets/`。
- HTML 仅使用相对路径、本地 CSS 和本地图片，不引用 CDN、在线字体、统计脚本、外部 JavaScript 或需要联网加载的资源。
- 双击 HTML 后，Windows 默认浏览器应可在离线状态完整阅读。
- 发布构建将 HTML 和资源目录复制到 `dist/Xuxia/`，与 `Xuxia.exe` 同级。
- 旧 `USER_GUIDE.html` 不得继续作为过时的第二权威说明书；实施时将其删除，或收敛为立即跳转到新手册的兼容入口。推荐删除并由新的中文文件名取代。

### 4.2 读者与语言

- 主要读者是普通 Windows 使用者，不假设掌握 Python、Git、命令行或 API 编程。
- 首版正文使用简体中文。
- Provider 名称、模型名、Base URL、API Key 等必要专有名词保留英文。
- 页面设计需支持浏览器缩放、打印和窄窗口阅读。

### 4.3 信息架构

说明书按实际任务顺序组织：

1. **认识序匣**：用途、适用场景、不会做什么。
2. **开始之前**：Windows 要求、网络要求、准备一个兼容 Provider API Key。
3. **首次配置 AI**：打开设置、选择或新增 Provider、填写 Base URL/模型/API Key、测试连接、保存；强调只需选择一个当前 Provider。
4. **界面导航**：Batch、Watch、Templates、System Status、Preferences 五个入口。
5. **五分钟快速上手**：导入 → 等待建议 → 审核/修改 → Apply → 必要时 Undo。
6. **批量重命名**：文件/文件夹导入、目标目录、搜索、9 个筛选项、选择语义、单项/批量 Apply、部分成功、停止、忽略、重试、清空工作区与 Undo 的区别。
7. **任务状态**：待处理、分析中、待确认、已撤销、已应用、失败、已取消、已忽略；必要时解释界面中的“全部”。
8. **文件夹监控**：源目录、可选目标目录、模板、递归、Review First、Auto Apply、暂停、ResourcePaused 与恢复；说明稳定/防抖和临时文件过滤。
9. **模板与受控词表**：字段、顺序、组织模式、日期格式、分隔符、输出语言；内置/自定义词条和 AI 新词条审核。
10. **图片、扫描件和视频**：图片缩放、扫描 PDF 安全页数限制、视频仅在本地提取关键帧并按图片分析，绝不暗示上传完整视频。
11. **资源限制、缓存与用量**：文件大小、PDF 页数、视频帧数、并发、失败重试、缓存清理和非货币调用记录；不出现价格或费用估算。
12. **隐私与数据流**：API Key 存系统凭据管理器；文本文件发送提取文本，图片/扫描件发送缩放图像，视频发送本地提取的 4–8 个关键帧；不上传不必要的完整原文件或完整视频；说明第三方 Provider 仍会接收必要内容。
13. **Undo 与文件安全**：建议生成/手改不写磁盘，只有 Apply/Auto Apply/Undo 写磁盘；扩展名保护、冲突自动编号、逐文件结果、历史日志与外部改动检测。
14. **诊断与故障排查**：连接失败、认证失败、429、超时、能力不支持、源文件变化、文件占用、ResourcePaused、缓存、诊断包。
15. **支持格式**：文档、图片、视频格式表。
16. **常见问题**：无建议、图片不能识别、为何未自动应用、如何恢复文件、能否使用自定义 Provider、是否必须用 DeepSeek/Qwen、是否收费。
17. **版本与支持边界**：手册对应序匣 1.0.0；不放公开竞品名称、研究证据或内部开发路径。

### 4.4 页面体验

- 顶部为序匣品牌、手册版本和一句用途说明。
- 桌面端使用固定/粘性目录栏，正文采用卡片式章节；窄窗口退化为顶部目录。
- 提供“快速开始”高亮路径，以及 Warning、Privacy、Tip、Error 四类信息框。
- 表格在窄屏可横向滚动，不破坏正文宽度。
- 支持 `Ctrl+F` 浏览器搜索；章节锚点稳定。
- 提供“打印/另存为 PDF”按钮，调用浏览器原生打印，不引入第三方脚本。
- 颜色对比符合可读性要求，不只依靠颜色表达错误/状态。

### 4.5 截图与真实性

- 只使用序匣自身当前版本的原生 Windows 截图。
- 不提交或展示第三方产品截图、第三方品牌或私有研究证据。
- 截图写入 `user-guide-assets/`，使用明确文件名，例如 `01-batch-empty.png`、`02-provider-settings.png`。
- 截图必须来自当前正式入口，中文可读、QML warnings 为 0，且不显示真实 Key、真实用户私密路径或个人文件。
- 使用本地合成数据和临时目录，所有敏感字段使用明显的示例值。
- 至少包含：主界面导航、Provider 设置、Batch 空态、Batch 混合任务、单项编辑、Apply/Undo、Watch 新建、Review First 结果、Templates、Vocabulary、System Status/Diagnostics。
- 如果某状态无法在不修改产品状态的情况下真实重现，使用 HTML/CSS 流程图解释，不伪造产品截图。

## 5. 打包与入口

- `packaging/xuxia.spec` 必须包含 `序匣用户手册.html` 和 `user-guide-assets/`。
- 新 Windows RC 中说明书应位于 `dist/Xuxia/序匣用户手册.html`。
- 首期不要求在 QML 内新增“帮助”导航入口；用户通过安装目录中的 HTML 打开。
- 若现有诊断/设置页已有适合的外部帮助动作，可在未来 backlog 增加，不能扩大本次范围。

## 6. 测试与验收矩阵

### 6.1 自动化

- QML：边界组件存在、颜色/宽度正确、普通/最大化可见性正确、鼠标不被拦截。
- QML：现有标题栏、导航、最小尺寸测试保持通过，warnings 为 0。
- HTML 结构：UTF-8、唯一标题、所有章节 ID 存在、内部锚点有效、所有图片相对路径存在、零外部网络资源、零占位符。
- 内容契约：不含“安装 Python/Git clone/多模态未实现/推荐同时配置双 Provider/API 价格”等过时信息；必须包含单一当前 Provider、关键帧、Review First、Auto Apply、Undo、隐私披露和 ResourcePaused。
- 打包：构建后的 HTML 和所有资源存在，EXE smoke 与版本资源测试继续通过。

### 6.2 人工/视觉

- 最大化边界隐藏，恢复后显示。
- 900×640 和 1000×700 无遮挡、裁切、滚动异常。
- HTML 在 Edge/Chrome 离线打开，桌面和窄窗口均可读。
- 所有截图中文清晰，无 tofu、真实 Key、真实私人路径或裁切。
- 打印预览不丢失标题、表格和警示块。

## 7. Definition of Done

以下条件全部满足才算完成：

1. 普通窗口的稍深灰 1px 边界经原生 Windows 视觉确认；最大化自动隐藏。
2. 新 HTML 手册内容与当前 1.0.0 产品一致，完全离线，无过时开发说明。
3. 手册截图均来自序匣当前正式入口，且通过隐私与可读性审查。
4. 手册和资源已包含在新 Windows RC 中。
5. 自动化、视觉、验收和打包 Gate 全部通过。
6. 未更新正式 Golden、未访问真实 API/Key/Credential Manager、未 push。

## 8. 回滚

- 窗口边界为独立 QML 层，出现问题时可移除该组件和两个 Design Token，不影响页面布局。
- 用户手册及资源为独立静态文件，打包项可单独撤销，不影响 EXE 核心功能。
- 实施使用独立提交，保证可以分别回滚“窗口边界”和“用户手册/打包”。
