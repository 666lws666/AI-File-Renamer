## 如何使用本轮程序

在本轮工作树的 `dist/Xuxia/` 中双击 `Xuxia.exe`。程序已经包含 Windows 运行能力，用户不需要安装 Python 或启动命令行服务。必须保留整个 `Xuxia` 文件夹，不能只拷走 EXE。

首次使用本地隐私模式时，选择工作区顶部的“本地隐私”，到设置中的“本地资源”准备模型。明确点击下载或离线导入后才进行资源获取；等待校验和实际自检成功，不能把“资源已校验”当作“模型已启用”。固定公共资源共 3,431,786,583 字节，程序已附带其中 18,425,079 字节的运行引擎 ZIP，模型及视觉资源共 3,413,361,504 字节。运行与暂存还需要额外磁盘空间，界面硬件检查不是最低内存或速度承诺。

建议先用几个非敏感文件试用：选择文件名语言和命名方式，添加文件，查看建议，必要时手动修改，再应用。应用前仍需自己核对名字是否准确。监控目录宜先用“先审核”；对没有完整内容覆盖证据的建议，自动应用会保留为待审核。

随程序提供以下离线手册，三者相互链接：

- `序匣用户手册.html`：简体中文。
- `user-guide-assets/manual-zh-HK.html`：繁体中文 香港。
- `user-guide-assets/manual-en-US.html`：英文。

原来的主检出与 `序匣.lnk` 没有被覆盖；它们不自动指向本轮候选。

## 已完成的产品与安全边界

1. 智能命名与模板命名共用提取、审核、编辑、Apply/Undo、扩展名及冲突保护。界面语言与文件名输出语言分开，不静默改变已有模板或 Watch 配置。
2. 云端与本地是独立处理选择。选中本地立即关闭后续云端提交，持久化、重试和 Batch/Watch 发布受同一代际权限约束。已经提交的云端请求不能撤回，旧结果不能重新发布；本地失败不自动切回云端。
3. 本地资源为固定来源、revision、大小及 SHA 256 的 Qwen3.5-4B 指令模型、Q4_K_M 量化、F16 视觉投影与 llama.cpp b10885 Windows CPU 引擎。离线来源只读，未知或损坏现场不擅自采用、清空或覆盖。
4. 下载、校验、自检在受管理后台执行，支持暂停/取消/重试并诚实区分资源 available 与服务 READY。明确联网同意只用于公共模型资源，不携带文件内容、文件名、路径或命名请求。
5. 文件内容只通过有上限的本地提取文本、缩放图片、扫描页或视频关键帧进入命名链路；不把完整 PDF、完整视频或源路径作为模型请求。超限、部分读取和依据不足不伪装成完整理解。
6. 本地模型由受管理 Windows AppContainer 及 Job 生命周期运行。真实子进程令牌已核验为 AppContainer、零 capabilities，关闭和取消持有真实所有者，不能只凭 localhost 认定隐私。
7. 原生文件操作只允许同卷，不覆盖已存在目标，拒绝目录链接，保留歧义完成或未知恢复证据。跨盘自动移动仍禁用，不能为便利改回不安全复制后删除。
8. 本地私密命名内容没有为“补齐缓存”而引入新的磁盘缓存。当前受管生产命名路径没有建议缓存的读写；未来启用缓存必须加入处理方式、模型、命名方式和语言的完整隔离上下文。

## 最终审查发现与处置

- 冻结 EXE 缺少 pywin32 动态加载的 `win32timezone`，导致本地资源 staging 失败。用真实 23 字节合成文件证明源码成功、原 EXE 失败、仅补 hidden import 后成功；已补打包断言并重新构建。没有放宽文件身份或安全校验。
- 云端混合 PDF 原先把“访问过页面”当作“实际读取了文字”，可能遗漏扫描页却允许 Watch Auto Apply。现在提取器记录真正有文字的页；缺失页只在允许的视觉能力范围内渲染。未知、禁止视觉、页数受限或渲染不足时必须保持部分覆盖、等待审核。新增真实混合 PDF 与真实 Watch 文件操作链路负向测试，未调用云端服务。
- 完整回归揭示一个空 PDF 图像夹具未提供新增的真实页数/页索引。仅修正夹具的两个元数据字段；原有“无法理解”和“不得调用适配器”的断言保持不变。

最终有边界的独立代码审查没有发现另一个确定性的阻断项。这是风险聚焦审查，不是逐行审完全部代码或完备安全证明；此前失败、中断和红阶段日志全部保留。

## 限制与普通维护待办

- 已验证当前机器的 CPU 运行链路，不保证其他 Windows 版本、所有硬件、GPU 或任意大小文件。扫描件实际样本需要分钟级处理，不承诺实时速度。
- 真实云端 API、供应商账单、真实密钥、Credential Manager 和私密用户文件没有用于测试。模拟请求可以证明协议及不发送边界，不能证明供应商当前可用性或真实模型命名质量。
- 不进行整台电脑网络采集。此处证据限定应用保护计数、受限子进程令牌与清理；“序匣不会上传文件内容或命名请求”不承诺控制其他软件或系统同步。
- 上次中断的 run05、其他旧 active journal 和未知 stage 原样保留；本次自有运行 clean 不能替它们背书，产品也不自动采用这些现场。
- 依赖弃用 warning、局部元数据防御和诊断细节进入维护待办，不为了消除措辞或警告重新扩展功能。直接低层使用 200 页本地参数与受管应用 100 页上限的统一、已有本地页事实精度及未来缓存接线仍需后续维护；当前用户路径限额及 Auto Apply 保护没有因此解除。
- 后续可在 EXE 内扩大扫描件、视频、Watch 与 Apply/Undo 的真实样本验证；本轮只通过表中实际执行范围，不以源码测试冒称已经全覆盖所有冻结工作流。
