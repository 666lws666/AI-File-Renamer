## 1. 产品概述

### 1.1 产品定位

序匣（英文代码名：Xuxia）是一款面向 Windows 的 AI 文件智能命名与归档工具。用 AI 让文件命名与归档井然有序。

AI-powered file naming and organization for Windows.

序匣利用可配置的云端 AI 分析文件内容和元数据，自动生成规范、可搜索的文件名，并支持按规则整理归档。核心原则：**AI 只产生结构化建议，绝不直接操作磁盘**；用户始终掌握最终决定权。

### 1.2 技术栈约束

| 维度 | 目标 |
|------|------|
| 平台 | Windows 桌面（后续可扩展 macOS/Linux） |
| GUI 框架 | PySide6 (Qt 6) |
| AI 后端 | 可配置的云端 API，通过可替换 Provider 适配层接入 |
| AI 架构 | **多模态**：文本分析使用文本模型，图片/扫描件/视频关键帧使用视觉模型 |
| AI 输出格式 | 严格 JSON（`response_format: {"type": "json_object"}` 或等效约束） |
| API Key 存储 | 系统凭据库（Windows Credential Manager）或加密用户配置；明文 JSON 不可接受 |
| 本地存储 | JSON 配置文件 + JSONL 操作日志 |
| 文件监控 | watchdog（OS 文件系统事件） |

### 1.3 首期 AI 供应商预设

序匣通过可替换的 AI Provider 适配层连接云端模型。首期提供以下供应商的预设配置：

| 供应商 | 说明 |
|--------|------|
| **DeepSeek** | 文本分析默认供应商 |
| **Qwen (通义千问)** | 视觉分析默认供应商 |
| **MiMo** | 首期预设 |
| **智谱 (GLM)** | 首期预设 |
| **Kimi (月之暗面)** | 首期预设 |

> **注意**: 首期不提供 OpenAI、Anthropic/Claude 品牌预设。当前代码中可能仍存在 OpenAI/Claude 遗留适配器，这是现状，不代表首期产品预设。是否删除或保留为隐藏兼容层将在后续实施计划中处理。

### 1.4 自定义供应商

序匣必须支持用户添加自定义供应商，配置项至少包括：Provider 显示名称、Base URL、Model、API Key、超时、重试策略、是否兼容 OpenAI 接口参数。AI Provider 架构必须可替换，不能写死到单一供应商。

### 1.5 已批准默认模型路由

| 场景 | 默认模型 | 说明 |
|------|----------|------|
| 文本分析 | `deepseek-v4-flash` | 文档、电子表格、演示文稿等可提取文本的文件 |
| 图片 / 扫描件 / 视频关键帧 | `qwen3.6-flash` | 多模态视觉理解 |
| 低置信度 / 高质量重试 | `qwen3.7-plus` | 或用户配置的其他高质量模型 |

### 1.6 支持的文件格式

| 类别 | 扩展名 | 提取方式 |
|------|--------|----------|
| **文档** | .pdf, .docx, .doc, .pptx, .ppt, .xlsx, .xls, .txt, .md, .rtf, .csv, .tsv, .html, .htm, .epub, .odt, .ods, .odp | 文本提取 |
| **图片** | .jpg, .jpeg, .png, .webp, .gif, .bmp, .tif, .tiff, .avif | EXIF/IPTC 元数据 + 多模态视觉内容理解 |
| **视频** | .mp4, .mov, .m4v, .mkv, .avi, .webm, .wmv, .flv, .mpeg | 文件属性 + 本地关键帧抽取 → 视觉模型 |
| **扫描件 PDF** | .pdf（无文本层或文本不完整） | 页面渲染为图像 → 视觉模型 |

## 2. 核心工作流

### 2.1 批量重命名（Batch Rename）— 主工作流

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌────────┐
│ Import  │───→│ Extract  │───→│   AI     │───→│  Review  │───→│ Apply  │
│ Files   │    │ Content  │    │ Suggest  │    │ & Edit   │    │ Rename │
└─────────┘    └──────────┘    └──────────┘    └──────────┘    └────────┘
                                                                     │
                                                              ┌──────┴──────┐
                                                              │    Undo     │
                                                              └─────────────┘
```

**阶段详解：**

#### 2.1.1 Import（导入）
- **触发**: 用户点击「添加文件」或「添加文件夹」
- **行为**: 扫描文件系统，过滤支持的类型，为每个文件创建 `FileItem`（状态: `PENDING`）
- **不写入磁盘**: 仅在工作区中建立待处理队列
- **容错**: 不支持的格式安静跳过；超大文件（>max_file_size_mb）跳过并记录
- **验证**: 文件存在性、可读性、大小限制

#### 2.1.2 Extract（内容提取）
- **触发**: 用户点击「扫描并 AI 分析」或自动触发
- **行为**: 根据文件类型分派提取器：
  - 文档 → 文本提取
  - 图片 → EXIF 元数据 + 图像内容（多模态模型）
  - 视频 → 文件属性 + 本地关键帧抽取 → 视觉模型
  - 扫描件 PDF → 页面渲染为图像 → 视觉模型
- **状态转换**: `PENDING` → `EXTRACTING` → `EXTRACTED`（或 `FAILED`）
- **可取消**: 用户可随时取消批量提取
- **进度报告**: 实时进度条 + 逐文件状态更新

#### 2.1.3 AI Suggest（AI 建议）
- **触发**: 内容提取完成后自动进入
- **输入**: 提取的内容（文本/元数据/图像描述） + 模板的 AI 提示词
- **输出**: 严格 JSON 结构
- **模型路由**: 根据文件类型和用户选择的质量模式自动选择模型（见 §6.4）
- **模板参与**: 当前选中模板的 `fields` 定义决定 AI 输出哪些字段；模板的 `system_prompt_override`（如有）替换全局 system prompt
- **状态转换**: `EXTRACTED` → `SUGGESTING` → `SUGGESTED`（或 `FAILED`）
- **文件名渲染**: `TemplateEngine.render(template, ai_fields, file_item)` → `suggested_name`
- **失败处理**: 网络错误、API 错误、JSON 解析失败 → 标记 `FAILED`，保留错误信息，可 Retry

#### 2.1.4 Review & Edit（审阅与编辑）

Batch 非空工作区采用**全宽滚动任务卡片队列**，不使用传统固定列 QTableView。

每个任务卡片呈现：状态指示、缩略图（如有）、建议文件名、原始文件名和选择状态。Hover 或选中时显示快捷操作。支持复选框选中后的批量操作。支持单项快捷 Apply。

- **搜索/筛选**: 按文件名搜索；按状态筛选
- **编辑**: 双击建议文件名可直接编辑 `final_name`
- **单项操作**: Ignore（跳过）、Retry（重试 AI）、单项快捷 Apply
- **批量操作**: 选中多项后批量 Ignore、批量 Retry、批量 Apply
- 批量内部仍按文件逐项执行并分别记录成功或失败
- 顶部有批次进度和操作区；Apply 期间有独立进度反馈
- **不写入磁盘**: 本阶段所有操作仅修改工作区数据

> **当前实现差距**: 遗留实现使用 QTableView/表格布局。这是现状，不代表新版目标基础。

#### 2.1.5 Apply（应用重命名）
- **触发**: 用户点击「应用重命名」（需确认对话框）
- **前置条件**:
  1. 至少一个文件状态为 `SUGGESTED` 且 `final_name` 非空
  2. 所有 `final_name` 已做文件名合法性校验
  3. 冲突检测已完成（同名文件 → 自动追加计数器 `_1`, `_2`）
  4. 目标目录存在或可创建
- **执行过程**:
  1. 按 `final_name` 排序（减少中间状态不一致窗口）
  2. 逐文件执行 `os.rename(old_path, new_path)`
  3. **每个文件独立成功/失败；不因单个失败终止整批**
  4. 每步写入 `RenameHistory`（JSONL）
- **状态转换**: `SUGGESTED` → `APPLIED`（或 `FAILED`）
- **冲突处理**:
  - 目标路径已存在 → 自动追加 `_N` 计数器
  - 目标目录不存在 → 自动创建
  - 文件被占用（PermissionError）→ 标记 `FAILED`，提示用户
  - 文件在处理期间被外部修改/删除 → 检测并标记 `FAILED`
- **结果报告**: 成功 N 个，失败 M 个；失败项列出原因

#### 2.1.6 Undo（撤销）
- **触发**: 用户点击「撤销上次」或 Ctrl+Z
- **范围**: 最近一次 Apply 操作的**整批**撤销（LIFO）
- **行为**: 读取 `RenameHistory`，将批次中每个文件从 `new_path` 移回 `old_path`
- **安全检查**:
  - `new_path` 必须存在
  - `old_path` 不得已被其他文件占用
  - 撤销过程每个文件独立成功/失败
- **批次标记**: 撤销后在 history 中标记该批次为 `undone=true`
- **多次撤销**: 可连续撤销多个批次（每次撤销最近一个未撤销批次）
- **重启后恢复**: 应用重启后，历史记录仍然可读，可撤销重启前的操作
- Undo 后的文件状态为「已撤销」，不得错误回到「从未处理」

### 2.2 文件夹监控（Watch Folders）— Pro 功能

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ File System  │───→│  Debounce    │───→│  Processing  │
│   Event      │    │  (2s wait)   │    │   Pipeline   │
└──────────────┘    └──────────────┘    └──────────────┘
                                               │
                                    ┌──────────┴──────────┐
                                    │                     │
                               Review First         Auto Apply
                                    │                     │
                              ┌─────┴─────┐        ┌──────┴──────┐
                              │  Pending  │        │ Extract → AI│
                              │  Queue    │        │ → Rename    │
                              └─────┬─────┘        └──────┬──────┘
                                    │                     │
                              User Reviews          History Logged
                              → Apply/Undo         → Undo Available
```

#### 2.2.1 监控配置
- 每个监控项包含：源目录、模板、目标目录、模式、递归开关、文件类型过滤
- 支持同时监控多个文件夹，各自独立配置
- 配置持久化到 JSON，应用重启后自动恢复监控

#### 2.2.2 Review First 模式
- 新文件检测后进入「待审阅队列」
- 队列在 UI 中可见
- 自动执行 Extract + AI Suggest（与批量重命名共享逻辑）
- 用户在队列中逐一审核，可编辑建议名、Ignore、或 Approve
- Approve 即触发 Apply（写入磁盘）
- **与批量重命名的关系**: 共享同一套预检、冲突处理、历史记录和 Undo 机制

#### 2.2.3 Auto Apply 模式
- 新文件检测后自动执行完整管线：Extract → AI Suggest → Apply
- **必须复用**与手动 Apply 相同的预检、冲突处理、历史记录和 Undo 机制
- 失败文件保留在队列中，显示错误原因，可手动 Retry
- 如果 AI 返回低置信度结果，自动升级至高质量模型重试

## 3. 状态模型

### 3.1 FileItem 状态机

```
PENDING ──→ EXTRACTING ──→ EXTRACTED ──→ SUGGESTING ──→ SUGGESTED
   │              │              │               │              │
   │              └──→ FAILED    └──→ FAILED     └──→ FAILED    ├──→ APPLIED
   │              (提取失败)     (提取异常)      (AI 异常)       │
   │                                                            ├──→ FAILED
   └────────────────────→ IGNORED                              │    (磁盘错误)
   (用户主动跳过)                                                │
                           APPLIED ──→ UNDONE (已撤销)          │
                                                                └──→ 可 Undo 回退
```

**目标可观察状态与筛选：**

| 内部状态 | 可观察筛选状态 | 含义 | UI 展示 |
|----------|---------------|------|---------|
| `PENDING` | **待处理** | 已导入，等待处理 | ⏳ 灰色 |
| `EXTRACTING` / `ANALYZING` | **分析中** | 内容提取或 AI 分析进行中 | 📖🤖 动画中 |
| `EXTRACTED` | **分析中** (过渡) | 内容已提取，等待 AI | 📄 蓝色 |
| `SUGGESTED` / `REVIEW_PENDING` | **待确认** | 建议已生成，等待审阅 | ✅ 绿色 |
| `APPLIED` | **已应用** | 已重命名，写入磁盘完成 | ✔️ 深蓝 |
| `FAILED` | **失败** | 处理失败 | ❌ 红色 |
| `CANCELLED` | **已取消** | 用户取消 | ⊘ 中灰 |
| `IGNORED` | **已忽略** | 用户跳过 | ⏭️ 灰色 |
| `UNDONE` | **已撤销** | 曾经 APPLIED，已被 Undo | ↩️ 浅蓝 |

- 「全部」是筛选选项，不是任务状态
- 临时执行状态（EXTRACTING/SUGGESTING）与可观察筛选状态（分析中）区分
- 「待确认」不能被 Suggested 一词隐去
- 「已撤销」必须进入产品状态模型和筛选
- Undo 后不得错误回到「从未处理」
- 状态、筛选、任务卡片展示、Acceptance Matrix 和不可妥协行为清单相互一致

### 3.2 批量操作状态

| 操作 | 前置条件 | 后置条件 | 副作用 |
|------|----------|----------|--------|
| Import | 文件路径有效 | PENDING | 无磁盘写入 |
| Extract | PENDING | EXTRACTED 或 FAILED | 无磁盘写入 |
| AI Suggest | EXTRACTED | SUGGESTED 或 FAILED | API 调用 |
| Edit Suggestion | SUGGESTED | SUGGESTED (final_name 变更) | 无磁盘写入 |
| Ignore | PENDING / EXTRACTED / SUGGESTED / FAILED | IGNORED | 无磁盘写入 |
| Retry | FAILED | 重新进入管线 | API 调用 |
| **Apply** | SUGGESTED + final_name 有效 | **APPLIED 或 FAILED** | **磁盘写入** |
| **Undo** | 存在未撤销批次 | UNDONE（恢复原文件名） | **磁盘写入** |
| Clear Workspace | (任意) | 清空工作区 | **无磁盘写入；不撤销已 APPLY 项；Undo 历史不丢失** |

## 4. 模板系统

### 4.1 模板结构

```
NamingTemplate {
    id: str (UUID)
    name: str ("通用命名模板")
    pattern: str ("{date}_{title}_{tags}.{ext}")
    separator: str ("_")
    date_format: str ("%Y-%m-%d")
    fields: [TemplateField]
    system_prompt_override: str | None  // 模板专属 AI 提示词
}
```

### 4.2 模板字段类型

#### AI 提取字段（由 AI 从文件内容生成）
- `date`: 文档日期 (YYYY-MM-DD)
- `title`: 文档标题/主题描述
- `type`: 文档类型 (contract, report, invoice 等)
- `tags`: 关键词标签 (1-3 个)
- `language`: 文档语言 (zh, en, ja 等)
- `subject`: 主题分类
- `creator`: 创建者/作者
- `project`: 项目名称

#### 系统变量（从文件系统获取，非 AI）
- `{ext}`: 文件扩展名（不含点）
- `{original_name}`: 原始文件主名（不含扩展名）
- `{file_type}`: 文件类型分类 (document/image/video)
- `{counter}`: 自动递增计数器（冲突时使用）

### 4.3 模板行为要求

1. **模板编辑即时生效**: 在模板编辑器中修改 pattern 后，工作区中已有 `SUGGESTED` 项的文件名预览应立即更新
2. **模板参与 AI 提取**: 模板的 `fields` 定义应传递给 AI（指定需要提取哪些字段）
3. **模板专属提示词**: 每个模板可配置独立的 system prompt，覆盖全局设置
4. **模板选择**: 批量重命名和 Watch Folder 均可选择模板
5. **默认模板**: 应用自带一个「通用命名模板」`{date}_{title}.{ext}`

## 5. 文件操作安全模型

### 5.1 操作分类

| 操作 | 读磁盘 | 写磁盘 | 不可撤销 | 说明 |
|------|:---:|:---:|:---:|------|
| Import | ✅ | ❌ | — | 建立 FileItem，不触碰文件 |
| Extract | ✅ | ❌ | — | 读取文件内容到内存 |
| AI Suggest | ❌ | ❌ | — | 仅 API 调用 |
| Edit Suggestion | ❌ | ❌ | — | 仅内存修改 |
| Ignore / Retry | ❌ | ❌ | — | 仅状态变更 |
| **Apply** | ✅ | ✅ | ❌ (可 Undo) | 执行 `os.rename()` |
| **Undo** | ✅ | ✅ | ❌ (可 Redo) | 反向 `os.rename()` |
| Clear Workspace | ❌ | ❌ | — | 仅清空内存状态；Undo 历史不丢失 |

### 5.2 写入前预检清单

Apply 操作前必须完成以下所有检查：
- [ ] `final_name` 非空且不含非法字符（已通过 sanitize）
- [ ] `final_name` 不包含路径分隔符
- [ ] `original_path` 文件存在且可读
- [ ] `original_path` 文件大小/修改时间未变化（与扫描时比较）
- [ ] 目标目录存在或可创建
- [ ] 目标路径不与已有文件冲突（或已通过计数器解决）
- [ ] 文件未被其他进程独占锁定（尝试性检测）

### 5.3 错误恢复

- **部分成功**: 如果批量 Apply 中第 N 个文件失败，前 N-1 个文件保持 APPLIED 状态，可单独 Undo
- **应用崩溃恢复**: 重启后读取 `RenameHistory`，标记未完成的批次供用户检查
- **冲突回滚**: 如果 Undo 时 `old_path` 已被占用，该文件保持现状并报告给用户

## 6. AI 集成规格

### 6.1 API 调用约束

| 约束 | 值 |
|------|-----|
| 输出格式 | 严格 JSON（`response_format` 或 tool calling） |
| Temperature | ≤0.3（低随机性） |
| Max tokens | 可配置，默认 4096 |
| 内容截断 | 可配置，默认 4000 字符 |
| 超时 | 30 秒 |
| 重试 | 3 次（指数退避） |
| API Key 保护 | 不写入日志；仅存凭据库或加密配置 |
| 速率限制 | 客户端串行调用，不并发 |

### 6.2 AI 输出规范

AI 仅输出结构化 JSON 字段，不直接生成文件名。文件名由 TemplateEngine 渲染。

```json
{
  "title": "2025年度销售报告",
  "date": "2025-03-15",
  "type": "report",
  "tags": ["销售", "年度报告", "2025"],
  "language": "zh"
}
```

### 6.3 多模态提取管线

| 文件类型 | 提取方式 | 模型 |
|----------|----------|------|
| 文档 (.txt, .md, .docx, .pdf 有文本层 等) | 文本提取 | `deepseek-v4-flash` |
| 图片 (.jpg, .png, .webp 等) | EXIF 元数据 + 图像内容 → 视觉模型 | `qwen3.6-flash` |
| 扫描件 PDF（无文本层） | 页面渲染为图像 → 视觉模型 | `qwen3.6-flash` |
| 视频 (.mp4, .mov 等) | 文件属性 + 本地抽取代表性关键帧 → 视觉模型 | `qwen3.6-flash` |

### 6.4 质量模式与模型路由

三种质量模式不是单纯调整 temperature 或 max_tokens。

**经济模式 (Economy)**：偏向用户配置的轻量模型；使用更严格的图片尺寸限制；关键帧数量偏向批准范围下限；限制自动高质量升级；仍受 ResourceGuard 安全上限约束。

**均衡模式 (Balanced) — 推荐默认**：在当前 Provider 内使用推荐模型；视频使用约 4–8 个代表性关键帧，受配置与资源限制；低置信度时可以按策略升级。

**高质量模式 (Quality)**：可使用当前 Provider 中用户配置的高质量模型；允许更宽松但仍受配置约束的图像尺寸；关键帧数量偏向批准范围上限；低置信度或手动高质量重试可升级一次；仍不得绕过 ResourceGuard。

- **低置信度自动升级**: 当 AI 返回所有字段为 "unknown" 或置信度评分低于阈值时，在当前 Provider 内按用户配置重试一次
- **非货币用量**: 记录请求次数、输入/输出 Token 与缓存命中，不展示价格或账单

### 6.5 ResourceGuard（Fail-Closed）

- 并发、队列、文件大小、扫描页数、视频帧数和失败重试均有硬上限
- 达到上限时不得静默发起或无限重试
- 应提示用户选择：减少文件、缩小图片、减少页面或帧数、等待冷却、切换经济模式，或取消任务
- 资源上限为安全约束，不是金额预算

### 6.6 图像本地预处理（缩放限制）

图片在发送视觉 API 前必须在本地预处理。可配置限制至少包括：最长边尺寸上限、总像素量上限、编码后字节大小上限、图片格式或压缩质量、单文件最多发送图像数量。

扫描版 PDF：只渲染需要分析的页面；页面在本地缩放；受最大页数、最长边、总像素和ResourceGuard 安全上限；不默认上传完整 PDF 二进制文件。

视频关键帧：使用与图片相同或等效的本地尺寸限制；发送前缩放或压缩；受关键帧数量和批次ResourceGuard 安全上限。

> 当前阶段没有批准具体默认像素值。这些阈值必须可配置。正式默认值应在实现阶段依据模型官方限制、成本和图像质量测试确定。验收使用「不得超过用户配置值」。

### 6.7 视频关键帧规范

1. 默认不上传完整视频。
2. 视频处理流程：本地读取 → 分析时长与元数据 → 本地抽取约 4–8 个代表性关键帧 → 本地缩放/压缩/组合 → 发送关键帧与元数据/摘要给视觉 Provider。
3. 关键帧选择不能仅机械固定为首、中、末三帧；可根据场景变化、时间分布或其他本地策略选取代表帧。
4. 关键帧数量：受用户配置、质量模式和 ResourceGuard 安全上限三重约束。经济模式偏向范围下限；均衡模式使用推荐范围；高质量模式偏向范围上限。不得突破用户配置和 ResourceGuard 安全上限。
5. 抽帧失败必须显示降级状态。降级时可使用文件名、元数据或已有 OCR/字幕信息，但不得伪装成完整视觉理解。

### 6.8 本地内容哈希缓存

缓存不能只使用文件路径或单独文件哈希。缓存匹配上下文至少应考虑：文件内容哈希、文件类型、内容提取器版本、OCR/扫描页渲染版本或设置、图片缩放/压缩设置、视频关键帧选择设置、模板 ID 或模板版本、Prompt 版本、结构化输出 schema 版本、Provider、Model、质量模式、输出语言，以及会实质改变命名结果的其他参数。

要求：缓存在本地；不保存 API Key；上下文变化时缓存必须失效；记录命中、未命中和失效原因；用户可清理缓存；用量记录区分真实 API 调用与缓存命中；不依赖供应商是否提供语义缓存。

## 9. 错误处理矩阵

| 场景 | 检测方式 | 恢复行为 | 用户通知 |
|------|----------|----------|----------|
| API Key 无效 | API 401 响应 | 提示配置，不崩溃 | 错误对话框 |
| API 速率限制 | API 429 响应 | 等待后自动重试 | 状态栏通知 |
| API 网络超时 | httpx.Timeout | 3 次指数退避重试 | 状态栏 + 日志 |
| 文件不存在 | `path.exists()` | 标记 FAILED，跳过 | 红色状态 + tooltip |
| 文件被占用 | `PermissionError` | 标记 FAILED，跳过 | 红色状态 + tooltip |
| 文件在管线中变化 | 比较 mtime/size | 标记 FAILED，警告用户 | 红色状态 + tooltip |
| 目标路径冲突 | `resolve_conflict()` | 自动追加计数器 | 黄色警告图标 |
| JSON 解析失败 | `json.JSONDecodeError` | 使用备用字段，标记低置信度 | 黄色状态 |
| 提取器崩溃 | 通用 Exception | 标记 FAILED，不崩溃 | 红色状态 + tooltip |
| 磁盘空间不足 | `OSError` (ENOSPC) | 终止批量操作 | 错误对话框 |
| 路径过长 (>260) | 预检长度 | 截断文件名 | 黄色警告 |
| ResourceGuard 上限触发 | 并发/队列/文件/页数/帧数/重试计数 | 暂停新任务并安全恢复；fail-closed | 状态提示 + 可操作建议 |

## 10. 隐私披露

### 10.1 始终在本地执行

文件扫描；文本提取；元数据提取；图片缩放和压缩；扫描页渲染；视频关键帧抽取；内容哈希计算；RenamePlan 生成后的文件操作；Undo 历史；本地缓存与用量记录。

### 10.2 向云端发送

| 文件类型 | 发送内容 | 不发送 |
|----------|----------|--------|
| 文本文档 | 必要的提取文本 + 元数据 + 模板/结构化命名请求 | 完整文档二进制 |
| 图片 | 本地缩放/压缩后的必要图像 + 元数据 + 视觉命名请求 | 原始分辨率图片 |
| 扫描件 | 本地渲染并缩放后的必要页面图像 + 已有 OCR 文本（如有）+ 元数据 | 完整 PDF 二进制 |
| 视频 | 本地抽取并缩放的约 4–8 个关键帧 + 摘要和元数据 | 完整视频文件 |

> 缩放后的图片、渲染页面和关键帧属于二进制/编码后的视觉数据。隐私披露不得使用「不发送二进制数据」或「AI 仅发送提取文本」等与多模态架构矛盾的表述。

### 10.3 用户可见披露

每次 AI 调用前必须向用户披露：目标供应商和模型、将发送的数据类型（文本/缩放图片/扫描页/视频关键帧）、当前质量模式、是否可能升级模型，以及适用的本地资源上限。

### 10.4 视觉 Provider 不可用时

显示明确降级状态；说明仅使用了文件名、元数据或 OCR；不得伪装成完整视觉分析。

## 11. 非功能性需求

### 11.1 性能
- 批量扫描 1000 个文件 < 5 秒
- UI 保持响应（后台线程执行管线）
- 任务卡片虚拟化（>1000 项不卡顿）

### 11.2 可靠性
- 管线执行中应用可安全关闭（提示用户等待或放弃）
- 崩溃不导致文件丢失或错误重命名（操作原子性最大化）
- 历史记录文件损坏时优雅降级（报告损坏批次，不影响新记录）

### 11.3 安全性
- API Key 不出现在日志、错误消息、导出文件中
- 文件操作限制在用户明确指定的目录内
- 所有文件处理均在本地执行，无原始文件上传（AI 调用仅发送提取的文本内容或图像帧至 API）

### 11.4 可用性
- 首次启动无 API Key 时引导用户配置
- 所有破坏性操作有确认步骤
- 错误消息使用用户语言（中文），包含可操作建议

### 11.5 云端 AI 透明度
- 使用者应知晓：AI 分析需要将文件中的文本内容和图像帧发送至所选云端 AI 服务商
- 非货币用量：设置界面显示请求次数、输入/输出 Token 与缓存命中，不显示价格、账单或金额预算
- 隐私披露：不发送原始文件；发送内容受缩放、截断和 ResourceGuard 安全上限约束
- 缓存：本地内容哈希缓存，同一文件和上下文不变化时免去重复 API 调用
- 用量记录：支持按 Provider、模型和内容类型查看，不记录 API Key、文件正文或完整路径
